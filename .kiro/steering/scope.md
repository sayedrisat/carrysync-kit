# Scope boundaries and evidence

This foundation was implemented by Codex, not Kiro. Kiro Requirements-First specs, custom agents, hooks and evidence must be created by the genuine future Kiro workflow. `docs/kiro-implementation-plan.md` contains proposals, not execution results.

Do not build complete teammate UI, introduce a backend/mock server, cloud synchronization, paid services, multipart transport or general-purpose CRDT machinery without a concrete need. IndexedDB is next; PWA and camera work follow separate acceptance criteria. No collaborator invitation without a provided username.

Keep code changes small, preserve existing work, commit only verified foundation/features and never commit credentials. Explicitly mark proposed APIs and remaining device work. Event-set convergence is conditional on compatible content; application-state convergence requires separate domain rules.
