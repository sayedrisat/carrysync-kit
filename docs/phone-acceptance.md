# Two-phone acceptance — Phase 4 offline reload and reopening

URL: **https://sayedrisat.github.io/carrysync-kit/**. Prior physical Phase 3 passes and the two reported bugs are [user-reported evidence](evidence/2026-11-03-user-reported-phase-3.md). The new Phase 4 phone checks below are **NOT RUN** by Codex. Copy the [evidence template](templates/phone-test-evidence.md), record real results and use public sample records only.

1. **Prepare online on both phones.** Use the same normal browser/profile that holds your existing records. Open the URL; note source commit, phone/OS/browser, device UUID, IDs/counts for both apps. Do not clear site data. If an update is cached, finish operations, close **all** CarrySync tabs/installed windows and reopen online. Wait for **Ready for Offline Use** on both. Optional: install through the browser's Install app / Add to Home Screen, open that same origin/profile, and verify its actual records/UUID/readiness too. Record whether testing a tab or installed window.
2. **Selection regression.** Select QuizRelay, reload online and confirm QuizRelay, its old records and UUID remain. Select FieldLedger and repeat. Counts/records must stay isolated. Return both phones to QuizRelay; record current UUIDs and event IDs/counts.
3. **Offline reload.** Enable airplane mode on both and explicitly turn Wi-Fi/mobile data off. Keep the same browser profile. **Reload both pages** and verify the app loads, QuizRelay stays selected, readiness returns, and old records/UUIDs match. This step must navigate/reload, not just keep the page open.
4. **Offline cold reopening.** Close all CarrySync tabs/installed windows on each phone; reopen the bookmarked/exact URL (or installed icon) while radios remain off. Verify shell, chosen app, existing IDs/counts and UUID. If feasible, separately terminate/restart the browser/app through the OS and repeat; record the exact termination method. Do not substitute a still-open tab for a closed-app test. Any unsupported/failed path is a real limitation, not a pass.
5. **Offline transfer after reopening.** On A: Create sample event → inspect event → Generate selected QR (≤1,200 UTF-8 bytes). On B: Start camera → allow if needed → scan A. Capture must stop; review must not add a record. Confirm: exactly one addition. Rescan/confirm: duplicate, zero additions. Create a **new** event on B and transfer to A. Repeat both directions and duplicates in FieldLedger; verify app isolation. No online decoder warm-up should be needed after readiness. Check manual scanner text review/confirm too.
6. **Offline validation and persistence.** Show a FieldLedger QR while B selects QuizRelay: WRONG_APPLICATION, no writes. Review `{`: INVALID_PAYLOAD. Modify an existing valid event's data but retain its ID: CONFLICTING_EVENT on confirm, original retained. Reload/reopen offline once more: new events, correct selection and UUID remain. Verify Stop/background/navigation turns off capture indicators; explicit Start is required on return. Record permission denial/manual fallback if tested.
7. **Reconnect/update.** Restore internet. Press Check / retry offline preparation and wait for readiness. If an update appears, close all app tabs/windows and reopen. Confirm records and UUID in **both** app namespaces are unchanged, then repeat offline reload. Never clear browser/site data as an update workaround.

Record pass/fail/NOT RUN per phone and path, screenshots with public fixtures, actual counts/IDs/bytes and exact messages. Installation on Android/iOS, OS termination and storage-eviction behavior are device-specific; desktop automation is not a physical result. Initial online preparation is mandatory. Full lifecycle/limits: [offline-pwa.md](offline-pwa.md). Hosting fallback: [https-deployment.md](https-deployment.md); changing origins creates separate browser storage.
